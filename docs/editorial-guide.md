# Как редактировать D&D Mini

После первого согласованного релиза V1.4.3 тексты меняются без Python и перезапуска. Отправленные сообщения меняются только при следующем обычном обновлении экрана.

## Каталог

По умолчанию: /var/lib/shpakdnd/editorial/ru. Для local/staging задайте MINI_EDITORIAL_DIR до запуска, например /tmp/mini-editorial-staging/ru. Это точный путь, ещё один ru не добавляется.

Исходные значения для справки — app/mini/editorial/defaults/ru. Не редактируйте их в production checkout. Внешние имена файлов совпадают с defaults: buttons.json, general.json, rules.json, glossary.json, icons.json, errors.json, effects.json и файлы разделов. Достаточно нужных ключей; прочее берётся из defaults. Schema.json менять нельзя.

## Кнопка

Внешний buttons.json:

~~~json
{
  "gacha.summon": "✨ Позвать героя",
  "general.back": "Вернуться",
  "navigation.back": "⬅️ Вернуться"
}
~~~

Действие, владелец и стиль останутся прежними. Helper добавляет fallback, если у кнопки зарегистрирована иконка. Другие ключи ищите в defaults и карте аудита.

## Сообщение и правила

Внешний general.json:

~~~json
{
  "onboarding.starter_message": "🎟 Твои первые 3 билета в инвентаре. Открой Гачу!",
  "handlers.launcher_text.line_01": "🎲 {name}\n\nПриключение начинается здесь!"
}
~~~

Внешний rules.json:

~~~json
{
  "rules.overview": "📖 D&D Mini\n\nНачни с быстрого старта и собери первых героев."
}
~~~

Сохраните все параметры исходного template с точным написанием. Нельзя использовать {player.name}, {items[0]}, выражения, !r или :format. Числа форматирует Python. Line_NN — закреплённый ключ, не текущий номер строки кода.

Большинство экранов — plain text: HTML там запрещён. HTML разрешён только schema соответствующего ключа; подставляемые имена экранируются. Длина проверяется; при чрезмерной подстановке используется исходный template. Boss имеет дополнительную защиту бюджета caption.

## Фракция и сокращение

Внешний glossary.json:

~~~json
{
  "faction.commoners": {
    "full": "Простые люди",
    "short": "Прост."
  }
}
~~~

Внутренний commoners не меняется. Full используется в карточке, short доступен компактным интерфейсам. Emoji и icon_key также зарегистрированы. Не переименовывайте коды и ключи.

## Иконки

Внешний icons.json:

~~~json
{
  "icon.gacha.summon": {
    "custom_emoji_id": null,
    "fallback": "✨"
  },
  "icon.section.duels": {
    "custom_emoji_id": null,
    "fallback": "⚔️"
  }
}
~~~

Опубликуйте свой Telegram Custom Emoji Pack, получите реальные ID и замените null строкой с реальным положительным числовым ID. Пустая строка, число без кавычек, отрицательное значение и произвольный текст не принимаются. Не копируйте случайные ID.

Иконки терминов на кнопках фильтра задаются теми же ключами: icon.faction.commoners, icon.damage.slashing и аналогичными. Они сохраняют прежний callback. Если исходная кнопка была без декоративного символа, её обычный вид остаётся прежним; назначенный ID добавляет custom icon после включения флага.

Для первого настроенного релиза MINI_CUSTOM_EMOJI_ENABLED=true включается после проверки доступа бота на стенде. Это флаг окружения процесса. Telegram предъявляет условия Premium владельца/Fragment usernames и типа отправки; сверяйтесь с актуальным Bot API.

Helper убирает обычную иконку при custom emoji. При выключенном флаге/null/старом aiogram остаётся fallback. HTML custom emoji сейчас поддержаны в объявлении дуэли. Остальные сообщения остаются plain text: не вставляйте tg-emoji в их JSON.

## Экипировка

Equipment.item должен начинаться [{bonus}] и иметь параметры name и slot. Бонус получает знак из игрового значения; префикс убрать нельзя. Слоты редактируются через slot.helmet, slot.ring, slot.cloak в glossary. Изменять бонусы, предметы и цены здесь нельзя.

## Проверка и доставка

Перед установкой:

~~~bash
python -m app.mini.editorial.validator --directory /tmp/editorial-review/ru
~~~

Команда называет ошибочный файл/ключ и возвращает ненулевой код. БД и Telegram не затрагиваются.

Через согласованный доступ администратора/SFTP доставляйте подготовленные JSON в staging вне checkout, проверьте их, затем установите. Пишите сначала в sibling .tmp, затем одной операцией переименуйте в .json. Не копируйте большой файл прямо в активный .json. Старую редакцию сохраняйте вне активного каталога или с расширением .bak.

Взаимозависимые файлы проверяйте вместе. Между отдельными заменами может примениться промежуточная корректная редакция. Для одной транзакции доставки объединяйте связанные изменения в один JSON или используйте согласованное атомарное переключение физического каталога. Не переключайте symlink: loader фиксирует разрешённый путь при старте.

Боту достаточно чтения. Только администратор/редакторы имеют запись. Типично root:shpakbot, каталоги 0750, JSON 0640; фактическую группу проверьте до установки. Не храните токены, .env и другие секреты. Внешний каталог не должен попадать в watcher, Git require_clean или удаляться deployment. Installed unit и права проверяются при первом релизе.

## Ошибка и откат

Повреждённая редакция целиком отклоняется, бот использует последнюю исправную и пишет причину в журнал. При первом запуске с плохим override используются defaults. Исправьте и сохраните атомарно — следующий запрос применит изменение.

Для отката верните предыдущий JSON либо удалите отдельный ключ/файл override. Перезапуск не нужен. Если ключ лежит не в своём файле, редакция отклонится.

Ошибка «Предмет … не складывается и уже есть у игрока» не редактируется: её текст является legacy-признаком пропуска при массовой административной выдаче. Это точечное исключение для сохранения механики.

Механики, HP, цены, rewards, вероятности, item effects, новые callback, сущности каталогов, SQL и schema требуют обычного релиза. Исторические snapshots и сохранённые игровые сообщения не переписываются редакторским JSON.

Ошибка кода требует отдельного решения об откате к проверенному релизу. При активном новом PvP старый код не завершит escrow: автоматический rollback запрещён до завершения игр/возвратов новым кодом и проверки очереди публикации. См. архитектуру V1.4.3. Старый код не читает внешний каталог. Не откатывайте SQLite из-за опечатки.

Перед выпуском пользователь проверяет на Telegram-стенде смену текста с тем же PID, повреждение/восстановление, активную игру, реальные emoji, длинные кнопки на телефоне и rollback. Эти реальные проверки ещё не выполнены.


## Новые карточки, PvP и учебник

hero.village.* в heroes.json задаёт строку жителя, кнопку и подтверждение выселения. Параметр job поступает из job.mine/market/hunt/none в glossary.json. Отображение работы не меняет назначение в SQLite. Старые heroshards/shardsell показывают hero.shards.closed; редакторский текст не может открыть продажу.

events_pvp.json содержит pvp.*: личные состояния, публичные объявления, результат, ошибки и навигацию. Не меняйте обещанные ставки/награды: 5 с каждого, общая выплата 8 победителю, 2 общих осколка проигравшему, полный возврат при ничьей/таймауте/отмене до принятия. Время и экономика заданы Python-константами, JSON на них не влияет. Названия вариантов — rps.saint/demon/villager в Glossary.

combat_guide.json содержит guide.title, previous/next/rules и title/body пяти глав: factions, damage, range, classes, traits. Сохраняйте все именованные параметры body; renderer подставляет существующие термины Glossary. Plain text: не вставляйте Markdown или HTML. Численные множители, проценты и смысл правил не являются редакторским произволом.

Например, для изменения заголовка первой главы во внешнем combat_guide.json:

~~~json
{
  "guide.factions.title": "1. Фракции героев и противников"
}
~~~

Значки новых кнопок используют icon.section.duels, icon.section.village и icon.guide.title. Все default Custom Emoji ID остаются null. В plain-text учебнике остаётся fallback; custom emoji на кнопках включаются штатным флагом. В реестре также зарегистрированы fallback классов, включая ▪️ для отсутствия класса.

При слишком длинной полной карточке фото сопровождается отдельным текстом, чтобы не удалить способность ради новой строки. Текст делится по лимиту 4096 UTF-16; заголовок фото остаётся в 1024. На телефоне это обязательно проверяется отдельно.

Матрица реального staging: docs/ui/v1.4.3-staging.md. Пока это план проверок, не подтверждение запуска стенда или релиза.

PvP safety добавляет pvp.error.paused, pvp.error.publication_pending и pvp.latest
в events_pvp.json/schema. Это только сообщения отказа и кнопка личного результата.
Maintenance, backoff и финансовые проверки управляются кодом/SQLite: override
не может их отключить. «Последняя игра» использует существующий owner/world-scoped
view; старые callbacks сохраняют проверки.
