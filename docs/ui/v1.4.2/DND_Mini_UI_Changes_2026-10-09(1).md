# D&D Mini — обновлённая карта UI по 17 изменениям

**Источник:** снимок `main` GitHub, commit `f06c0d129fdad0fef4fde0889915faac26b94f4a`. **Статус:** макет, не подключённый runtime JSON. Репозиторий не изменён.

## Что поменялось

1. `registration` объединён с `create_help`, добавлено прямое начало регистрации; для имени нужен новый безопасный обработчик, старая `/minicreate` остаётся резервом.
2. `created` удалён из карты: после успешного создания открывается `home` с одноразовым текстом «Персонаж создан! Теперь призови своего первого героя!» и информацией о стартовом подарке. Следующие открытия — обычный home.
3. `adventures` 2/2/1: Босс+Испытания; Ежедневный бой+Дуэли; Назад.
4. `heroarea` 2/2/1: Профиль+Инвентарь; Экипировка+Коллекция; Назад. Мифические герои временно перемещены в `more`, иначе вход в механику теряется; **согласовать расположение**.
5–6. `character` — улучшение активного героя и Главная/Назад. `character_no_hero` — Главная/Назад.
7–8. `gacha` 2/2/3, `gacha_result` 2/2/3; добавлены проектные `gacha_batch_result`, `gacha_coupon` для новых действий.
9. `collection` 1/2/2, новый отдельный `collection_favorites`.
10. `collection_all` и `collection_results`: по 4 героя на страницу, 2×2, затем ◀/page/▶ и Главная/Назад.
11. `collection_filter`: 6 параметров в 2 ряда по 3; ниже дополнительные служебные кнопки; Главная/Назад.
12. `inventory`: ровно 2 ряда, добавлена Главная.
13. `tower` и состояния: выбор героя+экипировка рядом, Главная+Назад рядом. При активном бою нельзя менять героя.
14. `tower_select` (редкость) → `tower_heroes_by_rarity` (список) → `tower_hero_card` (один герой, листание). Выбор героя остаётся на карточке; старые tower_selector_* отмечены deprecated, но не удалены до проверки старых callback.
15. `village` 2/3/2: Дома+Собрать (зелёная); Шахта+Рынок+Охота; Главная+Назад.
16. Новый `village_houses`: Купить; Поселить+Выселить. Отдельный `village_evict`. `village_add` остаётся открытым после поселения, список пересчитывается.
17. `village_mine`, `village_market`, `village_hunt`: Добавить+Убрать, Назад; для каждого новые экраны `<job>_add` и `<job>_remove`. Добавление показывает **только поселенцев без работы**, удаление — только работников выбранного здания. После назначения/снятия остаёмся на текущем экране, изменённый герой исчезает из доступного списка. Снять с работы != выселить.

## Требуется реализация / не считать существующим

- **Регистрация одним кликом до ввода имени**: нынешний /minicreate требует команду. Нужно выбрать безопасный способ ввода имени; не публиковать пользовательские данные в общей теме.
- **Призыв ×10**: отдельная атомарная операция (стоимость, влияние билетов/зелий/гарантов/дубликатов и временных бустов), защита повторных callback, корректные 10 результатов и сохранение состояния.
- **Купон**: нет согласованного контракта; определить тип, хранение, выдачу, активацию, экономику, лимиты, защиту повторов.
- **Состояния UI**: server-side `nav_back`, `visible_if`, пагинация/выбор героя/регистрация, контроль прав и длины callback_data <=64 bytes.
- **Деревня**: действующий service.mutate после изменения обрабатывается возвратом в home деревни. Нужны переработка UI callback navigation и фильтры без обхода правил idempotency/revision.
- **Башня**: новый многошаговый selector, сохранение героя этажа; нельзя менять героя во время попытки. Существующая проблема кнопки «Повторить бой» требует самостоятельной проверки.
- **Мифические герои**: прежняя кнопка убрана из heroarea; предложенный перенос в «Ещё» сделан, чтобы не оборвать доступ.
- **Изображения**: исходные динамические `image` сохранены. Новые экраны используют те же источники (например `{hero.image}`), не создают новых изображений.
- **Горячее редактирование**: JSON всё ещё только дизайн-карта; работающему боту понадобится отдельный renderer/loader, защита от невалидных JSON и учёт systemd watcher.

## Обязательные тесты и совместимость для Codex

До изменений: сравнить все текущие обработчики, согласовать новые игровые операции. Добавить unit-тесты разметки рядов/переменных/пагинации/условий; интеграционные тесты переходов и callback; регрессию старых кнопок после обновления; double-click/повторы/конкуренцию, restart/state recovery и SQLite; 10-круток с экономикой и недостаточным балансом; недоступных/занятых героев, смену героя башни, переезд/назначение/снятие жителей, одновременные действия и пустые списки; UI-тесты на стенде для Telegram.

Запустить полный `python -m unittest discover -s tests -q`, `python check_bot.py`, `python -m compileall -q bot.py app`, все validators и `git diff --check` на финальном коммите. Проверка фич без запуска тестов не разрешает слияние в main или прод. Deployment через предусмотренный release process только после отдельного подтверждения.

## Форматы JSON

- `DND_Mini_UI_Map_UPDATED_2026-10-09.json` — `buttons: [[...], ...]`.
- `DND_Mini_UI_Map_line1_btn_UPDATED_2026-10-09.json` — привычные `line1_btn`, `line2_btn`, ... для ручного редактирования.

`next_msg_id` — проектные ссылки, `actions` — метки, не исполняемый Python. Для кнопок со списками/условиями в `visible_if` указаны правила, а не исполняемые выражения.
