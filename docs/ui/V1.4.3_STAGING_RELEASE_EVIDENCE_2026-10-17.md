## Известные риски / требования

1. Утверждение оператора о PASS не заменяет скриншоты, Telegram trace и обезличенные per-session Wallet/shard receipts. C–V и X нуждаются в независимой оценке полноты доказательств.
2. `send` с утраченным Telegram `message_id` не может быть окончательно согласован без API идемпотентности: повторный `send` запрещён, монеты возвращаются; публичное сообщение может остаться. Permanent/exhausted edit может оставить устаревшую публичную запись.
3. Перед фактическим rollback с новой PvP-схемой обязательны `pause-new`, завершение/истечение ставок, reconciliation, `rollback-check=true`; без этого встроенные gate блокируют старый запуск. Production SQLite нельзя откатывать поверх новых пользовательских данных.
4. Новый документационный commit потребует повторного Linux CI и ревью точного нового SHA. Это не право автоматически слить PR или деплоить.

**Статус до устранения пробелов и повторной проверки:** «Релиз заблокирован». Merge в `main`, production deployment и rollback не выполнялись.
