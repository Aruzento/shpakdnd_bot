# D&D Mini V1.4.3: редакторская система

База: 5ab332e28ebef415a3b0757787109a8d60acd2a8, актуальная origin/main на начало работы. Ветка: codex/v1.4.3-editorial. Отдельный managed worktree сохраняет незакоммиченные изменения исходного checkout.

## Архитектура

app/mini/editorial/defaults/ru содержит проверенные исходные строки. Schema.json задаёт разрешённые параметры, типы, ограничения и ссылки на иконки и является частью релиза кода.

Loader читает defaults, объединяет частичные внешние переопределения и проверяет всю редакцию. Validation проверяет JSON, типы, placeholders, Telegram HTML и ID. Registry предоставляет text/glossary/icon и динамические совместимые Mapping/Sequence. Renderer подставляет только разрешённые имена и экранирует HTML-значения. Buttons сохраняет callback, стиль и остальные свойства aiogram. Middleware обновляет редакцию вне event loop перед update. Декоратор screen фиксирует один снимок для экрана и обслуживает фоновые публикации.

Внешний каталог: /var/lib/shpakdnd/editorial/ru по умолчанию либо точный путь MINI_EDITORIAL_DIR. Язык не дописывается. Путь внутри любого Git checkout отвергается. Миграций SQLite и редакторских таблиц нет.

## Hot reload

Сигнатура включает имя, mtime_ns, ctime_ns, размер и inode. Неизменившиеся JSON повторно не читаются. Изменённая редакция целиком проверяется под RLock. Повторная проверка сигнатуры не допускает публикацию файлов, меняющихся во время чтения. Глубоко immutable MappingProxyType заменяется одной операцией. ContextVar закрепляет снимок конкретного экрана.

Ошибка отклоняет всю редакцию: последний корректный снимок сохраняется, одна повреждённая сигнатура не спамит журнал. На первом запуске доступны валидные defaults. Исправление или удаление override применяется при следующем запросе. Defaults валидируются до polling. Изменение текста не публикует босса само по себе и не запускает watcher.

Async входы выполняют файловое чтение через asyncio.to_thread. Синхронные formatter вне event loop обновляются перед экраном; вложенные обращения используют закреплённую редакцию. Нового опроса SQLite нет.

## Охват

Подключены home, launcher и подменю; профиль, карточки и подбор героев; одиночная/пакетная гача, гарант и купоны; shop/inventory/effects; equipment; Boss private/public/selection/notices и публикация watcher; Tower/selection; daily/rules/onboarding; Events, Village, Duels, Mythic и Titles.

Presentation.py остаётся совместимым API для FACTION_LABELS, DAMAGE_LABELS, CLASS_LABELS, RANGE_LABELS, TRAIT_LABELS, RARITY_EMOJI и описаний свойств. Demon/demonic сохраняются. Полное/краткое имя, emoji и icon_key находятся в glossary; включены также слоты, ресурсы, разделы, статусы, работы и RPS.

Пользовательские ошибки доступны в errors.json. Заменены только аргументы исключений: классы ошибок, условия, транзакции, расчёты и idempotency keys сохранены. Отображаемые описания и названия эффектов берутся из effects.json; handlers зарегистрированных эффектов не меняются.

Equipment использует [{bonus}] {name} · {slot}. Знак вычисляется из реального attack_bonus: +56, +0, -12. Schema запрещает перенос префикса. Возврат Tower и пагинация сохранены. Старые equipped state без поля slot поддерживаются через ключ словаря.

V1.4.3-audit.json содержит все перенесённые выражения и оставшиеся строки с местами и причинами. docs/ui/v1.4.3-matrix.json обновляет формат Equipment в карте 109 экранов, сохраняя историческую карту V1.4.2.

## Исключения

Аудит оставшихся русских литералов включает SQL-комментарии, логи, validators и технические ошибки; его число не равно числу неперенесённых экранов.

- Игровые JSON content/heroes, boss/content, tower/floors и equipment/items не изменены. Их имена и описания следуют прежнему релизу контента.
- Hero/Enemy snapshots, turn_notice_json, payload_json, описания сертификатов/предметов и сохранённые сообщения пассивок не переписываются.
- В combat/hero_abilities, boss/boss_abilities, combat/creatures/classes и исходных данных событий остаются сообщения, создаваемые механическими событиями. Сохранённый event["message"] выводится без подмены; новые formatter notices покрыты. Дальнейший перенос должен сохранять код события и исторические snapshots.
- Исключение app/mini/admin_grants.py для уже имеющегося нестакающегося предмета сохранено в Python: grant_mini_item_all использует substring «не складывается» как legacy control flow. Редактирование этой ошибки запрещено; безопасное дальнейшее решение — отдельный тип исключения после обычного ревью механики.
- Технические ошибки каталогов, схемы, транзакционных preconditions и внутренние логи не редактируются.
- Часть вложенных fallback в доверенных динамических выражениях, чистые числовые/именные кнопки и навигационные символы сохранены. Имена сущностей не становятся идентификаторами действий.
- Старые RULES_TEXT/STARTER_MESSAGE доступны через __getattr__. Импорт str остаётся снимком времени импорта; все рабочие потребители используют rules_text()/starter_message(). SECTIONS и label mappings динамические.
- Суффикс line_NN — стабильный ключ formatter, а не номер строки Python. Его нельзя перенумеровывать.

## Telegram

Проверены Python 3.13.3 и aiogram 3.31.0 с icon_custom_emoji_id. Custom emoji выключены по умолчанию: MINI_CUSTOM_EMOJI_ENABLED=true включается после проверки доступа бота.

Названия glossary сохраняют semantic icon_key до фабрики кнопок: custom faction/damage/class/rarity icons доступны и в фильтре героев. Для plain labels обычный вид остаётся прежним до назначения ID.

Helper убирает исходную декоративную иконку перед custom ID или новым fallback. Callback/style не меняются. ID в defaults только null. При отсутствии ID/поддержки используется fallback.

HTML custom emoji подключены к существующему HTML объявлению дуэли. Имена игроков экранируются. Plain-text/caption экраны получают обычный fallback; глобальный parse_mode не меняется. Расширение HTML на них требует отдельного аудита transports.

Template limits учитывают UTF-16; callback ограничен 64 байтами. При чрезмерном динамическом результате renderer использует исходный template. Boss caption при превышении бюджета редакторской прозой повторно строится с defaults, сохраняя HP и награду. Feature descriptions добавляются только в свободный бюджет. Existing clipping/ephemeral UI сохранены; существующие ограничения очень длинных игровых имён остаются.

Источники: [aiogram](https://docs.aiogram.dev/en/dev-3.x/api/types/inline_keyboard_button.html), [Telegram Bot API](https://core.telegram.org/bots/api#inlinekeyboardbutton). Реальную отрисовку подтверждает только Telegram-стенд.

## Проверки, deployment и rollback

Tests/v1_4_3 проверяют ошибки, восстановление, атомарность, потоки, кеш, HTML, emoji, glossary, Equipment и reload 109 экранов. Existing suite проверяет duplicate/stale callback, экономику, restart и recovery. Проверки прежних констант адаптированы без удаления тестов.

Python tools/validate_editorial_release.py копирует код в temporary directory без .env и production SQLite, запускает check_bot.py, повторяет его на существующей тестовой БД и проверяет integrity_check, foreign_key_check, схему и число строк. Check_bot нельзя запускать рядом с production DB.

Watcher example дополнен только каталогами нового кода/defaults. Внешний /var/lib/... не входит в PathModified, require_clean и deployment. Реальный installed unit, права и сохранение каталога пользователю нужно проверить на стенде; живой сервер не обследован.

Первый релиз: ветка → проверки финального SHA → независимое ревью → staging → согласованный merge → согласованный deploy-shpakdnd. Merge, production deploy/restart и правки production .env/SQLite не выполнены.

Content rollback: восстановить JSON или удалить override атомарно. Code rollback: штатно вернуть прежний проверенный релиз; старый код не использует внешний каталог. SQLite из-за редакторской ошибки не откатывается.

GitHub Linux CI расширена матрицей Python 3.11/3.13 и редакторскими проверками; её фактический результат указывается отдельно после PR.

Реальные Telegram staging A–F, custom emoji, мобильные кнопки, PID живого бота и installed unit остаются обязательными ручными проверками. Локальная проверка PID относится к процессу теста.
