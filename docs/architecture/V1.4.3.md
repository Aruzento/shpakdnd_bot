# D&D Mini V1.4.3: редакторская система, карточки, PvP и учебник

База: 5ab332e28ebef415a3b0757787109a8d60acd2a8, актуальная origin/main на начало работы. Ветка: codex/v1.4.3-editorial. Отдельный managed worktree сохраняет незакоммиченные изменения исходного checkout.

## Архитектура

app/mini/editorial/defaults/ru содержит проверенные исходные строки. Schema.json задаёт разрешённые параметры, типы, ограничения и ссылки на иконки и является частью релиза кода.

Loader читает defaults, объединяет частичные внешние переопределения и проверяет всю редакцию. Validation проверяет JSON, типы, placeholders, Telegram HTML и ID. Registry предоставляет text/glossary/icon и динамические совместимые Mapping/Sequence. Renderer подставляет только разрешённые имена и экранирует HTML-значения. Buttons сохраняет callback, стиль и остальные свойства aiogram. Middleware обновляет редакцию вне event loop перед update. Декоратор screen фиксирует один снимок для экрана и обслуживает фоновые публикации.

Внешний каталог: /var/lib/shpakdnd/editorial/ru по умолчанию либо точный путь MINI_EDITORIAL_DIR. Язык не дописывается. Путь внутри любого Git checkout отвергается. Редакторская система не создаёт таблиц. Дополнительная PvP-механика имеет отдельную аддитивную миграцию v1_4_3 (см. ниже).

## Hot reload

Сигнатура включает имя, mtime_ns, ctime_ns, размер и inode. Неизменившиеся JSON повторно не читаются. Изменённая редакция целиком проверяется под RLock. Повторная проверка сигнатуры не допускает публикацию файлов, меняющихся во время чтения. Глубоко immutable MappingProxyType заменяется одной операцией. ContextVar закрепляет снимок конкретного экрана.

Ошибка отклоняет всю редакцию: последний корректный снимок сохраняется, одна повреждённая сигнатура не спамит журнал. На первом запуске доступны валидные defaults. Исправление или удаление override применяется при следующем запросе. Defaults валидируются до polling. Изменение текста не публикует босса само по себе и не запускает watcher.

Async входы выполняют файловое чтение через asyncio.to_thread. Синхронные formatter вне event loop обновляются перед экраном; вложенные обращения используют закреплённую редакцию. Hot Reload не опрашивает SQLite. Отдельный PvP watcher проверяет сроки и публикацию раз в 10 секунд.

## Охват

Подключены home, launcher и подменю; профиль, карточки и подбор героев; одиночная/пакетная гача, гарант и купоны; shop/inventory/effects; equipment; Boss private/public/selection/notices и публикация watcher; Tower/selection; daily/rules/onboarding; Events, Village, Duels, Mythic и Titles.

Presentation.py остаётся совместимым API для FACTION_LABELS, DAMAGE_LABELS, CLASS_LABELS, RANGE_LABELS, TRAIT_LABELS, RARITY_EMOJI и описаний свойств. Demon/demonic сохраняются. Полное/краткое имя, emoji и icon_key находятся в glossary; включены также слоты, ресурсы, разделы, статусы, работы и RPS.

Пользовательские ошибки доступны в errors.json. Заменены только аргументы исключений: классы ошибок, условия, транзакции, расчёты и idempotency keys сохранены. Отображаемые описания и названия эффектов берутся из effects.json; handlers зарегистрированных эффектов не меняются.

Equipment использует [{bonus}] {name} · {slot}. Знак вычисляется из реального attack_bonus: +56, +0, -12. Schema запрещает перенос префикса. Возврат Tower и пагинация сохранены. Старые equipped state без поля slot поддерживаются через ключ словаря.

V1.4.3-audit.json содержит все перенесённые выражения и оставшиеся строки с местами и причинами. docs/ui/v1.4.3-matrix.json сохраняет 109 исторических ID с актуальными кнопками, помечает закрытую продажу и добавляет новые экраны карточек, PvP и учебника отдельно. Историческая карта V1.4.2 сохранена.

## Исключения

Аудит оставшихся русских литералов включает SQL-комментарии, логи, validators и технические ошибки; его число не равно числу неперенесённых экранов.

- Игровые JSON content/heroes, boss/content, tower/floors и equipment/items не изменены. Их имена и описания следуют прежнему релизу контента.
- Hero/Enemy snapshots, turn_notice_json, payload_json, описания сертификатов/предметов и сохранённые сообщения пассивок не переписываются.
- В combat/hero_abilities, boss/boss_abilities, combat/creatures/classes и исходных данных событий остаются сообщения, создаваемые механическими событиями. Сохранённый event["message"] выводится без подмены; новые formatter notices покрыты. Дальнейший перенос должен сохранять код события и исторические snapshots.
- Исключение app/mini/admin_grants.py для уже имеющегося нестакающегося предмета сохранено в Python: grant_mini_item_all использует substring «не складывается» как legacy control flow. Редактирование этой ошибки запрещено; безопасное дальнейшее решение — отдельный тип исключения после обычного ревью механики.
- Технические ошибки каталогов, схемы, транзакционных preconditions и внутренние логи не редактируются.
- Часть вложенных fallback в доверенных динамических выражениях, чистые числовые/именные кнопки и навигационные символы сохранены. Имена сущностей не становятся идентификаторами действий.
- Старые RULES_TEXT/STARTER_MESSAGE доступны через __getattr__. Импорт str остаётся снимком времени импорта; все рабочие потребители используют rules_text()/starter_message(). SECTIONS и label mappings динамические.
- Суффикс line_NN — стабильный ключ formatter, а не номер строки Python. Его нельзя перенумеровывать.

## Telegram

Проверены Python 3.13.3 и aiogram 3.31.0 с icon_custom_emoji_id. Custom emoji выключены по умолчанию: MINI_CUSTOM_EMOJI_ENABLED=true включается после проверки доступа бота.

Названия glossary сохраняют semantic icon_key до фабрики кнопок: custom faction/damage/class/rarity icons доступны и в фильтре героев. Для plain labels обычный вид остаётся прежним до назначения ID.

Helper убирает исходную декоративную иконку перед custom ID или новым fallback. Callback/style не меняются. ID в defaults только null. При отсутствии ID/поддержки используется fallback.

HTML custom emoji подключены к существующему HTML объявлению дуэли. Имена игроков экранируются. Plain-text/caption экраны получают обычный fallback; глобальный parse_mode не меняется. Расширение HTML на них требует отдельного аудита transports.

Template limits учитывают UTF-16; callback ограничен 64 байтами. При чрезмерном динамическом результате renderer использует исходный template. Boss caption при превышении бюджета редакторской прозой повторно строится с defaults, сохраняя HP и награду. Feature descriptions добавляются только в свободный бюджет. Existing clipping/ephemeral UI сохранены; существующие ограничения очень длинных игровых имён остаются.

Источники: [aiogram](https://docs.aiogram.dev/en/dev-3.x/api/types/inline_keyboard_button.html), [Telegram Bot API](https://core.telegram.org/bots/api#inlinekeyboardbutton). Реальную отрисовку подтверждает только Telegram-стенд.

## Проверки, deployment и rollback

Tests/v1_4_3 проверяют ошибки, восстановление, атомарность, потоки, кеш, HTML, emoji, glossary, Equipment и reload 109 экранов. Existing suite проверяет duplicate/stale callback, экономику, restart и recovery. Проверки прежних констант адаптированы без удаления тестов.

Python tools/validate_editorial_release.py копирует код в temporary directory без .env и production SQLite, запускает check_bot.py, повторяет его на существующей тестовой БД и проверяет integrity_check, foreign_key_check, схему и число строк. Check_bot нельзя запускать рядом с production DB.

Watcher example дополнен только каталогами нового кода/defaults. Внешний /var/lib/... не входит в PathModified, require_clean и deployment. Реальный installed unit, права и сохранение каталога пользователю нужно проверить на стенде; живой сервер не обследован.

Первый релиз: ветка → проверки финального SHA → независимое ревью → staging → согласованный merge → согласованный deploy-shpakdnd. Merge, production deploy/restart и правки production .env/SQLite не выполнены.

Content rollback: восстановить JSON или удалить override атомарно. Code rollback: только по отдельному решению после проверки совместимости PvP escrow ниже; старый код не использует внешний каталог. SQLite из-за редакторской ошибки не откатывается.

GitHub Linux CI расширена матрицей Python 3.11/3.13 и редакторскими проверками; её фактический результат указывается отдельно после PR.

Реальные Telegram staging A–F, custom emoji, мобильные кнопки, PID живого бота и installed unit остаются обязательными ручными проверками. Локальная проверка PID относится к процессу теста.


## Дополнительный пакет после de3ce625: Village и карточки

ui/hero_village.with_village читает mini_village_residents по player_id + hero_id с JOIN владения и текущей ревизии. Персональные collection/profile, их повторное формирование после улучшения/активации и favorite получают свежий контекст. Gacha и публичный share не получают его. Строка hero.village.status использует job.mine/market/hunt/none из Glossary.

Кнопка выселения появляется только у жителя в collection/profile. Короткий base36 payload содержит hero_id, revision и источник карточки. load_extended_context проверяет owner/world/chat/topic. Первый callback показывает подтверждение; yes вызывает только village.service.mutate(action="evict", expected_revision=..., operation_key="hero-evict:<hero>:<revision>"). Действующий сервис учитывает производство до удаления жителя, освобождает место, сохраняет коллекцию, характеристики и дробные накопления. Дополнительная строка не сокращает имеющуюся способность ради caption. Очень длинный plain text делится по 4096 UTF-16 без разрыва Unicode code point. Ошибка фото использует текстовый fallback.

Продажа осколков закрыта во всех новых карточках. Старые heroshards/shardsell остаются зарегистрированы и проверяют контекст, затем возвращают уведомление; кошелёк и осколки не меняются, новые продажи не рисуются. sell_hero_shards сохранён как технический сервис, но старой Telegram-кнопкой продать уже нельзя. История не переписывается, upgrade работает как прежде. Legacy renderer продажи возвращает закрытое состояние только с кнопкой назад.

## PvP Events: состояние и экономика

Новый pvp.py использует тот же rps_outcome, что Solo, без случайного соперника. Вход Events → Святоша, Демон, Житель разделён на «Против бота» и «Против игрока». Прежние ev:rps/bets/start/pick/again/turn callback сохраняются.

mini_event_pvp хранит world/creator/acceptor, уникальный (creator,operation_key), stake=5, status, сроки, winner/outcome, revision и состояние публикации/ID сообщения. mini_event_pvp_members хранит пару (session,player), неизменяемый после записи choice и active. Частичный UNIQUE(player_id) WHERE active=1 запрещает две активные PvP-сессии. Связи FK и CHECK аддитивны. Старые mini_event_sessions и Duels не преобразуются.

Переходы:
- create → open: создание, членство и −5 монет создателю в одном BEGIN IMMEDIATE.
- open → choosing: первый подходящий соперник, −5 монет, членство, условный UPDATE и срок выбора в одной транзакции. Собственный/чужой world/недостаток монет отклоняются.
- choosing → finished: второй скрытый выбор, результат и выплаты в одной транзакции. Победитель получает всего 8 монет (чистый итог +3), проигравший 2 общих осколка (итог −5 монет). Ничья возвращает обоим по 5 без осколков.
- open → cancelled/expired/publication_failed: возврат создателю.
- choosing → expired: возврат обоим без иных начислений. После принятия отмена запрещена.

Wallet helper пишет operation_key pvp:<id>:stake/refund/winner:<player>. Shards helper вызывается только при единственном переходе активной сессии в finished под BEGIN IMMEDIATE: состояние и выдача коммитятся вместе. UNIQUE участников, терминальный status и условные UPDATE защищают повтор callback и restart; Python Lock не используется для финансовой корректности.

ACCEPT_SECONDS и CHOICE_SECONDS — по 120, ставка/награды заданы в коде. Watcher проверяет persisted сроки каждые 10 секунд; сервис также истекает сессии при обращении. Взаимное исключение Solo/PvP проверяется в обе стороны под SQLite-транзакцией. Hero Duels совместимы: у них отдельный hero lock, PvP героя не резервирует; кошелёк общий и атомарный, прежние ставки/награды Duels сохранены.

## Telegram-публикация и восстановление

Публичный callback owner=0 разрешает только join/view, проверяет world, зарегистрированного игрока и chat/topic. Персональные pick/cancel проверяют owner; view проверяет членство. До двух ответов публичный текст не содержит выборов. При принятии обоим направляется ephemeral экран; недоставленный экран открывается из Events либо публичной кнопки. Итоговое сообщение содержит оба выбора и не имеет управляющих кнопок.

pending → sending — единственный SQLite claim перед sendMessage. Token, время и lease 45 секунд хранятся в БД; HTTP timeout — 25 секунд. Подтверждённый отказ Telegram даёт failed, timeout/потеря ответа/пустой message_id — uncertain. Ошибка или истёкший send lease атомарно закрывают активную игру и возвращают все удержанные ставки через Wallet. Повторного send нет, recover не крадёт живой lease другого процесса. Принятие возможно только после подтверждённого send с известным ID: результат нельзя выдать во время неопределённой отправки. Поздний ответ может сохранить ID, но не возобновляет закрытую/возвращённую игру.

Доставленное с потерянным ответом объявление может остаться в Telegram без обновления: ID неизвестен. Его кнопки проверяют SQLite и отклоняют закрытую игру. Результат/возврат участник открывает через «Последняя игра» в личном меню PvP, даже если старое сообщение удалено.

Edit выполняется только для известного ID. Persisted edit_token/edit_revision и lease сериализуют handler/watcher/процессы. Ошибка сохраняет retry_count, next_retry_at, edit_status, безопасные тип/описание и время. Повторы: 10, 30, 60, 120, 300, 900, 900 секунд; восьмая последовательная неудача завершает очередь как exhausted. Telegram 429 удлиняет задержку до retry_after, 400/403 останавливают её как permanent. Успех сбрасывает счётчик и ошибку; «message is not modified» подтверждает только захваченную ревизию. Новая ревизия остаётся dirty; устаревший ответ не снимает чужой lease и не сбрасывает backoff. Новое состояние не оживляет exhausted/permanent. Экономика независима от доставки. Лог — одна структурированная запись на переход ошибки, без имён, скрытых выборов, токенов и raw exception.

Аддитивная v1_4_3_safety добавляет поля публикации, mini_event_pvp_control и mini_event_pvp_shard_awards. По умолчанию paused=0. Старый inflight edit переводится в retrying с сохранением более позднего lease deadline и минимум 10 секунд backoff; повторный init не сбрасывает его. Исторические ошибки заменяются безопасным описанием. Участники, выборы, средства и результаты сохраняются.

pause-new — только явное операторское действие. Проверка внутри BEGIN IMMEDIATE create/accept блокирует и старые кнопки, SQLite считает отказы. Та же транзакция завершает open с Wallet-refund; choosing продолжает выбирать/истекать. Повторный pause не выдаёт деньги снова, restart сохраняет режим. При неоднозначном ledger новые входы блокируются, спорная игра остаётся для ручной проверки.

Новая победа атомарно сохраняет receipt loser/+2 вместе с прежним начислением. Диагностика сравнивает точный multiset Wallet каждой сессии и receipt, а не общий баланс. Legacy win без receipt помечается legacy_shards_unverified: миграция не выдумывает историю; операторское свидетельство возможно только после внешней сверки, без ремонта ресурсов. Команды — [PvP operations](../operations/PVP.md).

## Учебник

Пять plain-text глав ui/combat_guide.py доступны через отдельный guide callback из существующих правил; rulespage совместим. Все тексты и навигация находятся в combat_guide.json/schema. Термины берутся из существующих Glossary и Icon Registry; Техник — отображаемое имя canonical class.technical, коды не меняются.

matchups.py подтверждает ×2/×0.25/×1; creatures.py — аддитивные −10% физического типа и −10% melee, flying и свойства; classes.py — численные классовые эффекты. Пояснены округление долей монет вверх, независимость class_tag/class_name, особенности трёх щитов Испытаний без монетного фонда Boss и версия старых боёв. Tower не вызывает creatures.battle_start: стартовые undead/armored бонусы там не применяются; при последнем сломанном щите попытка заканчивается до poison_tick. Boss ability engine (magic_shield/mechanism) в Tower не вызывается; учебник сообщает это явно. Боевые алгоритмы, каталоги и вероятность гачи не менялись.

## Проверки, deployment и rollback

tools/verify_editorial_mechanics.py продолжает сравнивать 30 прежних gameplay-модулей с базой, восстанавливая редакторские строки. Единственное разрешённое расширение старой логики — точная пара import/call assert_no_active_pvp в Events._start; валидатор требует ровно эту пару и сравнивает остальной AST. Новый PvP не объявляется редакторской эквивалентностью: отдельные unit/integration/race/restart тесты проверяют его транзакции.

tools/validate_pvp_migration.py архивирует код 5ab332e (V1.4.2), de3ce625 (редакторская V1.4.3) и 6773986 (PvP до safety), создаёт заполненные синтетические SQLite с героями/ресурсами и незавершёнными Solo/Duels, мигрирует трижды и сравнивает 58/60 старых таблиц. Для 6773986 проверяются девять заполненных состояний PvP, включая inflight edit: допускается только перевод служебного lease/ошибки, экономика и выборы неизменны. Повторный init сохраняет новые поля. Отдельная копия с новым активным escrow проверяет startup прежнего кода, integrity/FK и сохранность новых строк. Fresh install также проверяется трижды. CI выполняет инструмент на Python 3.11/3.13.

Перед будущим deployment обязательны независимое ревью нового SHA, реальный staging по docs/ui/v1.4.3-staging.md, backup и штатные release checks. Существующий watcher охватывает app/mini/events и migrations; внешний редакторский каталог остаётся вне него. Production не использовался.

Фактический rollback() выполняет frozen deploy/pvp_ops.py rollback-check до checkout, непосредственно перед checkout и после старых checks перед startup. Helper использует только stdlib, SQLite mode=ro/query_only со snapshot и WAL; не импортирует исчезнувшее приложение, не читает .env и не мигрирует. Проверяет integrity/FK, схему, pause-new, отсутствие active escrow, точную экономику и разрешённую очередь публикации. Любая неопределённость блокирует переход, обхода нет. Backup автоматически не восстанавливается.

До будущего согласованного релиза необходимо отдельно обновить установленный root bundle через installer: старая команда не получает guard автоматически. Regression tests запускают настоящий Bash rollback с fake Git/systemd и реальной временной SQLite, проверяют изменения между gate, missing/corrupt DB, failed startup и исчезновение source после checkout. Production systemd/права и реальная Telegram-доставка требуют стенда. Статус — «В разработке», staging A–X обязателен.
