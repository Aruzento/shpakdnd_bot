# D&D Mini V1.3.1 — follow-up

Реализованы только скрытое отображение `/superluck` и общий выбор активного героя
до старта Boss. Онбординг, титулы, Tower, Equipment и остальные части V1.3.1
сохранены. Баланс и алгоритмы боя/призыва не изменены.

## Скрытый superluck

Раскрытие было в двух местах:
- `app/mini/ui/heroes.py::_format_gacha`: отдельная строка «Персональная гарантия… Legendary 100%»;
- `app/mini/gacha.py::get_gacha_state`: замена показываемых шансов на 100% Legendary / 0% остальных редкостей.

Строка удалена. Публичные шансы рассчитываются как для обычного призыва,
с учётом существующего видимого зелья удачи. Административная гарантия
по-прежнему сохраняется в БД, выбирает Legendary при успешном призыве и
расходуется в той же транзакции. Неудачная оплата её не расходует.
`forced_legendary` остаётся внутренним полем сервиса и результата для admin/debug.

Проверены меню, preview, карточка/caption, новый герой, дубликат, кнопки повтора,
публичная публикация героя, ephemeral результат и callback toast. Они не выводят
состояние, источник, количество или причину административной гарантии.
Обычный flow и отображение зелья удачи сохранены.

## Общий active hero

Единственный источник выбора до старта — `mini_players.active_hero_id`.
Существующий `set_active_hero()` и Boss `select_battle_hero()` используют одну
операцию `set_active_hero_in_transaction()` с проверкой владения героем.
В Boss проверка регистрации/статуса и смена глобального героя выполняются под
одним SQLite write lock, который также используется при старте боя.

Новая регистрация не заполняет `mini_boss_participants.hero_id`.
Для announced/ready `list_participants()` читает глобального активного героя,
включая имя и ID. Старые pre-start значения участника не задают отдельный выбор.
Коллекция и Boss используют одни данные; изменение через любой интерфейс
сразу видит другой при открытии/обновлении.

При старте существующая транзакция сохраняет текущий active hero в participant:
ID, ATK с учётом звёзд, фракцию, тип урона, класс, дальность, особое свойство,
passive key/text. Дальнейшая смена active hero не перезаписывает снимок.
Fighting/recovered Boss использует сохранённый loadout. Восстановление старых
снимков осталось прежним и не переводит их на текущего героя игрока.

Админ-защита удаления героя соответствует lifecycle: до старта проверяет
глобальный active hero, после старта — сохранённого героя боя. Тексты выбора
Boss и только связанные абзацы Правил обновлены.

## Схема и совместимость

Новые изменения схемы и миграции не нужны: имеющиеся nullable hero_id,
active_hero_id и snapshot поля достаточны. Миграция основного V1.3.1 остаётся
без изменений. Старые начавшиеся Boss sessions не мигрируются на нового героя.

## Regression coverage

Добавлено 14 тестов в `tests/v1_3_1/test_followup.py`: скрытые меню/шансы,
кнопки/caption нового героя и дубликата, ephemeral результат/toast,
независимость зелья удачи, реальные callbacks Collection/Boss, единственный
pre-start выбор, ready/start, legacy pre-start, restart active hero/snapshot,
ATK со звёздами и пассив после смены героя, старый fighting loadout, отказы,
админ-защита удаления и конкурентный start/selection.

Существующие tests обновлены только под новый выбор/пользовательское отображение.
Две старые подготовки пассивов теперь читают active_hero_id до старта;
проверки mockery/emergency salvage и наград сохранены.
