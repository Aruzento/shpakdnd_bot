## Уточнения и сильные стороны

Service boundaries daily/shop/gacha/items/Events уже существуют; новый service
framework не нужен. Public Boss media/deduplication вынесены в public.py и
сохраняются. Pure-ish hero/Boss engines, integer faction arithmetic,
connect_mini_db, operation keys, transactional writes, immutable loadouts,
legacy battle recovery и content safety имеют сильный regression suite.
Class/special/feature tags намеренно открыты: фиксировать закрытый enum нельзя.

Аудит охватил app/, tests/, root и deploy/: bot startup и 8 routers, обычные
D&D SQL/services/timers, Mini context/transport, catalogs и validations,
coins/shards, item use, Boss hooks/rewards/watcher/schema и deploy watcher.
Обычные D&D подсистемы не требуют перестройки для Tower; замеченный исторический
create.py router не включён в ROUTERS, это вынесено в технический долг.

## Дополнительно найдено

Тесты patch'ят зависимости старых handlers, поэтому требуются прямые aliases
и адресные изменения patch targets. Assertions сохраняются. check_bot мутирует
схему и каталоги; дальнейшие проверки требуют копии. Mini DDL ранее не имел
общей явной транзакции, в отличие от Boss migrator. Pure hero engine можно
перенести механически; объединение его с Boss abilities увеличит сцепление.

## Решение

PROCEED: shared UI; screen subrouters; Boss UI split; public wallet API;
shared combat and hero hooks; Boss calculations/runtime/repository/rewards;
ordered idempotent schema modules; effect registry; documentation cleanup.
Главные риски — transaction atomicity, порядок hooks, snapshots, legacy shards
и ephemeral send/delete. Проверки идут после каждого этапа и отдельных combat
переносов. Gameplay/content V1.3+ не добавляются.
