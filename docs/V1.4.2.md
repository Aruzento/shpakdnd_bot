## Planned additive migrations (recorded before implementation)

- `dnd_items`: stable scoped item definitions, unique scope/code and normalized name.
- `dnd_currencies`: item FK, exact positive decimal denomination; one base per scope.
  Store a Decimal numerator and a positive integer `currency_quantity` denominator,
  so ratios such as 3 coins = 1 base coin remain exact without float or rounding.
- `inventory.item_id`: nullable FK; preserve all legacy rows without automatic merging.
- `mini_gacha_pity`: one row per Mini player, bounded nonnegative counters 10/25/85.
- `mini_purchases.operation_key/result_json`: replay protection for shop buttons.
- Spirit lantern charges use existing `mini_player_effects`; frozen battle guarantee uses existing participant JSON snapshot. No new ownership or effect tables.

All migrations run only against disposable test databases during development.
Production merge, deployment, rollback and production migration require separate authorization.
