## 1. Чёрный фон: правила PNG, графика и защита от ложной ошибки

Файл: `app/mini/mythic/content.py::png`; вызовы из `validate_mythics` и `app/mini/mythic/raid/catalog.py::validate`.

1. Сначала **прочесть и диагностировать четыре угловых RGBA-пикселя каждого реального PNG** из `app/mini/content/hero_images/{ice,lightning,dark,fire,star,earth,moon,sun}_{egg,young,adult}.png` (24 шт.) и `app/mini/mythic/raid/images/raid_boss_{1,2,3,4}.png` (4 шт.). Отчёт — путь, размеры, тип PNG, все четыре угла и валидность. Не выводить необоснованных оценок «не чёрный фон» при значениях RGB 1–4. Учитывать, что оттенки вне углов, антиалиасинг, тени и художественная композиция допустимы.
2. Для **чёрного фона** разрешить только отдельный, минимальный документированный допуск **`0 <= R,G,B <= 4` поканально, `alpha == 255`**, исключительно для проверки четырёх углов предоставленных Mythic и Raid PNG. Это не универсальный допуск для любой картинки и не смягчение CRC, PNG signature, квадратности, корректности scanline, transparency, валидности файла или безопасности путей. 5 и выше, alpha 254 и ниже — **FAIL**. Если реальные углы выходят за пределы 0–4, не расширять допуск самовольно: отразить точные значения как блокер художественной поставки.
3. Сохранить существующий белый контракт только для S5: RGB 252–255 включительно по каждому каналу, alpha строго 255.
4. **Обязательно включить `background=0` при проверке четырёх рейдовых изображений**, в том числе через `catalog.validate(... require_images=True)` и общий `--strict-content`; сейчас боссовская проверка работает без требования цвета фона. Не применять этот контракт к посторонним изображениям, для которых чёрный фон не утверждён.
5. Сохранить целые байты всех 45 авторских PNG; до/после SHA-256 должен совпасть. Точечный фикс валидатора лучше правки артов. Существующие 17 S5 проверять как есть.
6. Unit-тесты RGB 0,1,2,3,4 / 5, 252,255 / 251, alpha254/255, различные PNG color modes, все 4 угла, повреждение CRC/scanlines, невалидный файл, отсутствие PNG, неверная размерность. Интеграционные тесты с **настоящими** 24 Mythic и 4 Raid PNG, независимо от наличия карточек героев, плюс отдельная проверка 17 S5.

## 2. Реально импортировать 17 S5: учесть, что изображения уже лежат в целевой директории

Источники: `docs/v1.5/S5_IMPORT_MANIFEST.json` (17 уже утверждённых записей, не редактировать их игровые поля), `app/mini/content/hero_images/` (17 PNG уже есть). Инструмент: `tools/import_v15_s5.py`.

**Критическая ловушка, выявленная при ревью:** нынешний `--apply` безусловно бросает `Refusing to overwrite existing asset`, если PNG уже находится в `HERO_IMAGES_DIR`; именно таково текущее состояние ветки. **Исправить импортёр**, а не копировать те же изображения повторно и не удалять их.

Алгоритм:

1. До записи проверить текущий HEAD, 17/17 S5-источников и images; dry-run (`--source docs/v1.5/S5_IMPORT_MANIFEST.json --images app/mini/content/hero_images`) должен PASS. Не импортировать из произвольного незнакомого каталога.
2. Для **уже существующего целевого PNG**: проверить валидность, имя, сравнить с требуемым источником (по возможности sha256 байтов), а если `source == destination`, корректно обработать идентичный путь без копирования. Если имена совпадают, но содержимое отличается, **FAIL до любой записи**, без перезаписи чужих артов. Если изображения отсутствуют, импортировать только проверенное содержимое и только из разрешённого входного каталога.
3. `--apply` должен **атомарно добавить только отсутствующие 17 hero records** в соответствующие `common.json`, `uncommon.json`, `rare.json`, `legendary.json`, без удаления и изменения существующих героев и без модификации `S5_IMPORT_MANIFEST.json`. Подтвердить распределение `5/6/4/2`, уникальность code, актуальные способности/теги/ссылки/фракции, корректную регистрацию через общий каталог.
4. Защитить повторный `--apply`: не начислять/не создавать копии и не портить catalog; сделать безопасный `already imported / no-op` при полном идентичном совпадении кодов и полей (или явно документированный отказ без изменений при частичном/конфликтном состоянии). **Частичный, несовместимый набор — отказ**, не заменять ничего автоматически. Перед записью всех каталогов провести полную валидацию, использовать безопасную запись во временные файлы/backup и rollback при ошибке.
5. Проверить, что новые S5 участвуют только в разрешённой обычной гаче, а Mythic/Shadow **не попадают в стандартную гачу**; валидатор не опирается на старые фиксированные количества `54` или пустой каталог. Проверить GUI/карточки, выдачу дубликатов, осколков, рангов, пассивки и снаряжение по существующим правилам.
6. Работать только в `codex/v1.5`, без SQLite production, с тестовыми одноразовыми БД. Зафиксировать пост-импорт diff и список exact codes. Отметить, если исходный каталог уже импортирован другим коммитом: в этом случае только валидация/совместимость, никаких дублей.
