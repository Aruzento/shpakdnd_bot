# Авторский JSON Историй

Сценарии — данные, без исполняемого кода и экономики. Разместить реальные `.json` во внешнем `STORIES_DIR` (например, штатный `/var/lib/shpakdnd/stories`), вне Git/watcher. Не требуется рестарт. Повреждённый/дублированный файл изолирован от валидных сценариев и показывается в диагностике администратора.

Общие корневые поля: `schema_version` (строго целое 1 или 2), уникальный `code` (1–48 латинских букв/цифр/_/-), `title`, `description`, `start_node`, `nodes`. `nodes` — объект 1–1000 узлов; узел имеет `text` и либо `end: true`, либо `choices` (1–20 вариантов). Вариант имеет только `id`, `text`, `next`; id уникален внутри узла (до 20 латинских символов/цифр/_/-), next указывает на существующий узел. Все узлы достижимы от start_node и из каждого есть путь к настоящему `end: true`. В v1 циклы запрещены (DAG); в v2 обязательно `visit_policy: "once"`, циклы в авторском графе разрешены, повтор узла внутри прохождения запрещён. `visit_policy` в v1 отклоняется. Вложенные условия/скрипты/награды/неизвестные поля отклоняются. Файл не symlink и не более 2 MB.

Текст узла до 3500 UTF-16 units, заголовок до 150, описание до 1000, выбор до 120. Повторяющиеся JSON-ключи/ID узлов отклоняются до построения словаря. Текст отправляется с parse_mode=None, авторский HTML не исполняется. Голосовые кнопки содержат только серверные session_id/step/index; имена длинных узлов не помещаются в callback.

Команды в нужном чате/теме:

- `/story list` — администратору список валидных файлов и ошибок.
- `/story CODE` — открыть запись; одна открытая/активная сессия на chat/thread (None нормализуется в 0).
- `/story start` — администратор фиксирует текущий валидный JSON и состав. После запуска изменения файла не влияют на эту сессию.
- `/story status` — текущий узел/состав/проценты, в том числе после рестарта.
- `/story kick TELEGRAM_USER_ID` — администратор убирает участника и его голос текущего узла, пересчитывает кворум.
- `/story cancel` — администратор завершает сессию без экономики. Повторное прохождение открывается новым `/story CODE`, с независимым session_id.

Игрок выбирает настоящего D&D-персонажа своего username в этом чате либо собственный Mini-аккаунт этого чата; типы можно смешать. Быстрое создание D&D сохраняет characters + character_profiles с level=1. Для Mini используется существующая регистрация, после неё есть возврат к Истории. После старта состав фиксирован, самостоятельного выхода/переголосования нет. Ждём всех оставшихся, без таймаута; при нуле участников нужна отмена. При равенстве выбор случайный, сохранён один раз. Денег, предметов или боевой валюты сценарий не выдаёт.

## V2: одно посещение на группу

Маркеры принадлежат session_id всей группы. При старте посещён только start_node;
при подтверждённом переходе добавляется следующий узел. Голос, статус и выбор при
ничьей до commit ничего не отмечают. Источник истины — текущий story_sessions.node_id
и node_id/next_node всех story_steps этой сессии. Рестарт восстанавливает тот же набор.
Новая сессия после завершения/отмены имеет независимый набор. Миграция не нужна.

Доступен только исходный выбор, цель которого не посещена и из которого существует
путь к end:true без посещённых узлов. Проверка идёт по frozen snapshot_json, повторяется
в транзакциях vote/tally/advance/kick. Исходный индекс choice сохраняется в callback
story:vote:sid:step:index даже после фильтрации; скрытый/старый индекс сервер отклоняет.
Проценты считаются среди допустимых выборов. При повреждённом маршруте без выхода
публикуется диагностический текст без кнопок, состояние сохраняется, /story cancel
остаётся доступной администратору; ошибка содержит session/step/node/visited в журнале.

Тест сравнивает все 53 текста и 113 выборов/ссылок с оригиналом (удалены только **,
заголовки сцен включены в текст). Литературные награды не изменяют кошельки/инвентарь.
