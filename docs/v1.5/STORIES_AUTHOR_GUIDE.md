# Авторский JSON Историй

Сценарии — данные, без исполняемого кода и экономики. Разместить реальные `.json` во внешнем `STORIES_DIR` (например, штатный `/var/lib/shpakdnd/stories`), вне Git/watcher. Не требуется рестарт. Повреждённый/дублированный файл изолирован от валидных сценариев и показывается в диагностике администратора.

Корневые поля: `schema_version: 1`, уникальный `code` (1–48 латинских букв/цифр/_/-), `title`, `description`, `start_node`, `nodes`. `nodes` — объект 1–1000 узлов; узел имеет `text` и либо `end: true`, либо `choices` (1–20 вариантов). Вариант имеет только `id`, `text`, `next`; id уникален внутри узла (до 20 латинских символов/цифр/_/-), next указывает на существующий узел. Все узлы достижимы от start_node, циклов нет. Вложенные условия/скрипты/награды/неизвестные поля отклоняются. Файл не symlink и не более 2 MB.

Текст узла до 3500 UTF-16 units, заголовок до 150, описание до 1000. Текст отправляется с parse_mode=None, авторский HTML не исполняется. Голосовые кнопки содержат только серверные session_id/step/index; имена длинных узлов не помещаются в callback.

Команды в нужном чате/теме:

- `/story list` — администратору список валидных файлов и ошибок.
- `/story CODE` — открыть запись; одна открытая/активная сессия на chat/thread (None нормализуется в 0).
- `/story start` — администратор фиксирует текущий валидный JSON и состав. После запуска изменения файла не влияют на эту сессию.
- `/story status` — текущий узел/состав/проценты, в том числе после рестарта.
- `/story kick TELEGRAM_USER_ID` — администратор убирает участника и его голос текущего узла, пересчитывает кворум.
- `/story cancel` — администратор завершает сессию без экономики. Повторное прохождение открывается новым `/story CODE`, с независимым session_id.

Игрок выбирает настоящего D&D-персонажа своего username в этом чате либо собственный Mini-аккаунт этого чата; типы можно смешать. Быстрое создание D&D сохраняет characters + character_profiles с level=1. Для Mini используется существующая регистрация, после неё есть возврат к Истории. После старта состав фиксирован, самостоятельного выхода/переголосования нет. Ждём всех оставшихся, без таймаута; при нуле участников нужна отмена. При равенстве выбор случайный, сохранён один раз. Денег, предметов или боевой валюты сценарий не выдаёт.

Фикстура схемы есть только в `tests/v1_5/test_boss_stories.py`, игровые сюжеты Codex не сочинял.
