## Ограничения отката

Успешный запуск старого кода на мигрированной копии доказывает совместимость чтения схемы. Он **не доказывает безопасный рабочий rollback**: старый бот не завершает новые рейды/Stories, не обслуживает активные пет-часы/универсальную валюту и может показывать старые механики гачи. Новый код также не должен изменять уже замороженные старые бои и их таймеры.

Перед любым отдельно разрешённым откатом приостановить новые старты штатным способом, завершить или согласованно отменить новые активные процессы, урегулировать escrow PvP, сохранить все новые ledgers/runtime/external JSON. Не обрезать новые таблицы и не восстанавливать старый DB backup поверх прогресса игроков без отдельного решения владельца. O01 теперь задаёт точную компенсацию; использовать только авторизованный сервис/confirm с этой формулой, не ручные SQL-начисления.

Предпочтительный технический путь исправления — новый feature commit с сохранением данных. Возврат старого кода/БД, конкретный сценарий drain и компенсации требуют отдельного разрешения и проверенного плана. Изменение watch.path в Git только добавляет новые кодовые каталоги; внешние сценарии/настройки/SQLite/.env не добавляются в наблюдение.

Completion-аудит меняет только logger call deploy-скрипта в Git: Python redactor игнорирует grouped INT/TERM, tee -i игнорирует INT; основной bash сохраняет trap/cleanup/exit130/143. Это разрешённая адресная правка на fake PTY fixtures, не запуск deployment. tools/validate_deploy_bundle.py сравнивает protected baseline и разрешает строго одну строковую замену; original tests/helpers неизменны. Красный final CI означает BLOCKED независимо от baseline.


ИтерацияO01–O10: newpolicyversion2/counterconfirmed сохраняются в новыхsnapshots, oldactiveversion1/positive-only не переписываются. Новые mini_star_rewards/cancel_requests и Towerresult_json аддитивны. Старый код может прочитать базовуюсхему, но не обслуживает новыеcancel/Star/runtime/activepet процессы; oldstartupнаcopy не разрешаетlive rollback. Перед будущимоткатом согласованныйdrain,backupвсехновыхжурналов/runtime/externalcontent и проверка отдельнойкопии.
