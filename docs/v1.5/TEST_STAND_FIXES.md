## Производительность

Подтверждённая CPU-причина: raid.catalog.load синхронно декодировал четыре PNG при каждом открытии
и повторно при создании рейда. Локальный замер до: 4.480/4.502 секунды.
После: первая полная проверка 6.725 секунды, повторные загрузки 0.01045/0.01038 секунды.
Это замеры одной Windows-машины; они не измеряют сеть TEST.

Ключ кэша включает точный JSON и SHA-256 байтов PNG, а вызывающий получает независимую копию.
Повреждение PNG или смена JSON требует полной строгой проверки. Каталог прогревается до polling.
Синхронные операции Mythic выполняются в worker threads; транзакции и идемпотентные операции не разделяются.

Фото зверей повторно использует успешно полученный Telegram file_id отдельно по bot ID и SHA-256.
На замену картинки кэш не распространяется; ошибочный file_id один раз заменяется новой загрузкой.
Кэш ограничен 24 изображениями; данные игроков не сохраняются.

Лог mini_callback_timing содержит только фиксированные поля: screen, update_dispatch/total,
context, sqlite/connect, catalog, pet/raid render/operation, worker_cpu_ms, max_loop_lag_ms,
Telegram API method durations и image_api/image_prepare. SQL, аргументы, callback_data,
Telegram IDs, пользовательские тексты, URL и токены не логируются.
SQLite timing включает ожидание execute/BEGIN. Вложенные метрики нельзя складывать как независимые.
Получение update измеряется от dispatcher: Telegram не передаёт timestamp создания callback.
Реальные API/VM замеры требуют согласованного обновления TEST; текущий TEST не перезапускается.

## Временно выключенные режимы

MINI_DUELS_ENABLED и MINI_PVP_ENABLED по умолчанию выключены.
Гейты стоят в UI и перед созданием новых сервисных транзакций. Нельзя открыть/принять новую
дуэль/PvP. Таблицы, история, балансы, escrow и код сохранены.
Recovery/watcher не изменены. Только ранее утверждённые expiry/refund/payout продолжают
обрабатывать старые операции; отключение флагов само не вызывает maintenance/drain или возврат.

Read-only снимок VM-338333: pending duels=0, duel locks=0, active PvP members=0,
незавершённых публикаций/редактирований=0, два завершённых PvP-матча.
Перед переключением обновить наблюдение. При активном escrow — отдельное согласование.

Для включения позже: отдельная приёмка, инвентаризация операций и ledger через deploy/pvp_ops.py.
Неоднозначные операции блокируют включение. Не аннулировать ставки и не применять maintenance
для очистки. Включить только согласованный флаг в TEST .env, пересчитать env hash в policy,
получить свежее штатное разрешение запуска. Одного показа кнопок недостаточно.
Старые тесты включают режимы только в scoped fixtures, сохраняя проверки прежнего кода.
Новые тесты проверяют default-off и отсутствие финансовых изменений.
